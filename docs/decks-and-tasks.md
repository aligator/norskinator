# Decks, data and task types

Read this before changing exercises, decks, task types or how an item is presented.

## Data, task types and decks

Content and presentation are separate (`src/core/types.ts`):

- A **data item** has a `DataKind`: `cloze` (sentence with one gap, answer,
  `alternatives` that are also correct, `distractors`, optional `hint`) or
  `sentence` (a whole sentence, its word `tiles`, other correct orders as
  `alternatives`).
- A **task type** (`src/core/tasks.ts`) turns an item of one data kind into an
  `Exercise`: `multiple-choice` or `type-in` for cloze, `word-order` for
  sentences (`TASK_DATA_KIND` in `types.ts`).
- A **deck** is a list of sources, each a pool of items plus the task types
  it is practised with. `loadDeck` checks that they fit.
- SRS history belongs to the item, not the task type. Each presentation picks
  a task type by the learner's `taskWeights`: shares within one data kind,
  always 100 % per data kind (`src/core/task-weights.ts`).

The preposition deck has two pools:

- `authored.json` — sentences written with AI for this app, in template form:
  an entry is one sentence, or a pattern with a `{slot}` and `fillers`. Every
  sentence carries its permanent id, translations and alternatives.
  `content.test.ts` validates it.
- `tatoeba.json` — generated by `pnpm run data`, never edited by hand.
  `overrides.json` adds reviewed alternatives, AI translations and
  exclusions on top, keyed by item id.

The adjective deck has one pool, `tatoeba.json` (generated) plus
`overrides.json`, which can also replace an item's `tags` and set its
`explanation`. Each item carries a `hint` (the dictionary form, «stor»), shown
in the empty gap and as the type-in placeholder. Its first tag is a form
category from `categories.ts`, the second `type:<inflection>`.

The word-order deck has one pool of `sentence` items, `tatoeba.json` plus
`overrides.json`. The learner sees the translation and orders the shuffled
tiles; its first tag is a rule from `categories.ts`.

`src/decks/tatoeba-source.ts` maps a generated bundle to items for all three
decks: a bundle item with `options` becomes a cloze item, one with `tiles` a
sentence item.

## Adding a topic

1. Create `src/decks/<topic>/index.ts` exporting a `Deck` with its sources.
2. Add it to `DECKS` in `src/decks/registry.ts`.

Nothing else changes: scheduler, stats and UI are deck-agnostic.

## Adding a question format (task type)

1. Add a member to the `ExerciseKind` enum and to `TASK_DATA_KIND` in
   `src/core/types.ts`, and add the exercise shape to `Exercise`. A new shape
   of content also needs a `DataKind` member and its item type in `DataItem`.
2. Add it to `TASK_TYPES` in `src/core/tasks.ts` (data kind, label, builder).
3. Handle the new case in `src/core/checker.ts`, and in the store's and
   resume's options handling if it shows choices.
4. Render it in `src/ui/modules/practice/exercise-card.ts`.
5. Give it a share in `DEFAULT_TASK_WEIGHTS` (`src/core/task-weights.ts`);
   the shares of one data kind add up to 100.

TypeScript's exhaustiveness checks point at every spot that needs work.
